## Программы:

1. **chat2_server.c**  
   Выбранный вариант задания - чат 2. Серверу на вход подается номер порта, далее он создает свой сокет, готовится к соединению с клиентами, открывает (создает) дополнительный файлы для взаимодействия клиентов внутри сервера. В первом бесконечном цикле вначале происходит ожидание подключение очередного клиента, далее завершаются предыдущие процессы-клиенты, обновляется база никнеймов. Потом в цикле for для каждого клиента обновляется база ушедших клиентов и запускается отдельный процесс-сын взаимодействия сервера с каждым отдельным клиентом, после создания всех процессов происходит новая итерация бесконечного цикла и сервер снова ожидает подключения нового клиента. В каждом клиентском процессе сначала происходит проверка на "онлайн" данного клиента, далее, если это последний (только что подключившейся) клиент, запрашивается его никнейм с проверкой на уникальность, потом сообщение о подключении рассылается всем остальным. Далее для всех клиентов запускается бесконечный цикл с обновлением базы никнеймов, получением от клиента сообщения и обновлением базы ушедших клиентов. Потом идет классификация сообщения - служебная команда или обычное сообщение. Если служебная команда, то определяется, какая именно: \user - проверка баз никнеймов и ушедших клиентов и отправка данному клиенту всех, кто сейчас онлайн, \quit ..msg.. - рассылка всем другим пользователям сообщение об уходе вместе с прощальным сообщением и выход из бесконечного цикла - завершение работы данного клиента, \private ..usr.. ..msg.. - разделение всего сообщения на никнейм и само сообщение, если ник онлайн, отправка ему приватного сообщения, \privates - отправка данному клиенту списка всех тех, кому он отправлял приватные сообщения через отдельный массив, \help - отправка клиенту описания всех возможных команд. Если сообщение обычное, то оно отправляется всем клиентам онлайн. Также реализованна обработка сигнала SIGINT для клиентких и серверного процесса с закрытием всех сокетов.
   
2. **chat2_client.c**
    Клиенту на вход подаются IP и номер порта. Сначала происходит настройка сокета на взаимодействие с сервером, далее вводится никнейм клиента до подтверждения сервером его уникальности. Потом создается 2 отдельных процесса - для принятия и для отправки сообщений. Если была введена команда \quit, то процессы завершаются.
